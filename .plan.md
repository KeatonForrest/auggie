## Phase 2: Reliability Hardening (prevent double-charging)

### 2a. Fix idempotency race condition — `db/idempotency.py`, `api/idempotency.py`
- Current: between check and save, concurrent requests both execute
- Fix: use `INSERT ... ON CONFLICT DO NOTHING RETURNING` as an atomic lock claim
- New flow: `claim_idempotency_key()` inserts a "pending" row → if insert succeeds, proceed → save result on completion. If insert conflicts, poll for the result.

### 2b. Make bulk credit deduction atomic — `api/routes.py`, `db/bulk.py`
- Current: `use_credit()` and `create_bulk_job()` are separate calls
- Fix: new `create_bulk_job_with_credit()` function wrapping both in a single transaction (same pattern as `create_job_with_credit`)

### 2c. Add retry backoff to task queue — `migrations/019_task_queue_run_at.sql`, `db/task_queue.py`
- Add `run_at TIMESTAMPTZ DEFAULT now()` column to `task_queue`
- `claim_next`: add `AND run_at <= now()` filter
- `fail()`: set `run_at = now() + interval * 2^attempts` (exponential backoff)

### 2d. Fix stale requeue incrementing — `db/task_queue.py`
- `requeue_stale` currently doesn't increment `attempts`
- Hanging tasks get requeued forever
- Fix: increment attempts on requeue so they eventually hit max_attempts

### 2e. Add advisory lock to migration runner — `db/_migrate.py`
- Two concurrent startups can race on migrations
- Wrap migration loop in `SELECT pg_advisory_lock(hash)` / `pg_advisory_unlock`

**Verification:** Run test suite, deploy two instances simultaneously, verify no duplicate credit charges.

## Phase 3: Developer Experience Polish (the "wow" factor)

### 3a. Add rate limit headers to every response — `main.py` (middleware)
Add middleware that injects on every response:
- `X-RateLimit-Limit` — max requests per window
- `X-RateLimit-Remaining` — requests left
- `X-RateLimit-Reset` — seconds until window resets
- Already have the data in `InMemoryRateLimiter`; need to expose it

### 3b. Add request ID to every error response — `main.py`
- Currently `X-Request-ID` is in response headers but NOT in the error body
- Change error envelope to: `{"error": {"code": "...", "message": "...", "request_id": "..."}}`
- Makes debugging trivial: "my request failed" → "what's the request_id?" → instant log lookup

### 3c. SDK: Add User-Agent header — `sdk/auggie/__init__.py`
- Set `User-Agent: auggie-python/0.3.0` on both clients
- Allows server-side tracking of SDK versions, helps debug version-specific issues

### 3d. SDK: Fix `create_list` default mismatch — `sdk/auggie/__init__.py`
- SDK defaults `analyze=True`, API defaults `analyze=False`
- Align SDK to match API: `analyze=False`

### 3e. SDK: Add webhook signature verification — `sdk/auggie/__init__.py`
```python
@staticmethod
def verify_webhook(payload: bytes, signature: str, secret: str) -> bool:
```
- Developers receiving webhooks need this. Every webhook-capable API provides it.

### 3f. SDK: Add `bulk_research_and_poll` convenience method — `sdk/auggie/__init__.py`
- `research_and_poll` exists for single jobs but not bulk
- Add equivalent that polls `get_bulk_job` until completion

### 3g. Add request/response access logging — `main.py` (middleware)
- Log every API request: method, path, status code, latency, request_id
- Currently only slow requests (>1s) are logged
- Essential for debugging and monitoring

**Verification:** SDK tests, check response headers with curl, verify webhook verification works.

## Phase 4: Production Operations

### 4a. Credit audit trail — `migrations/020_credit_ledger.sql`, `db/credits.py`
New `credit_ledger` table:
```
id, org_id, amount_cents, balance_after, operation (charge/refund/topup),
reference_type (research/enrich/bulk/list), reference_id, api_key_id, created_at
```
- Every credit mutation gets a ledger entry
- Enables billing dispute resolution, usage analytics, and debugging

### 4b. Periodic completed task cleanup — `worker.py`
- Completed tasks accumulate in `task_queue` forever
- Add periodic cleanup: archive/delete completed tasks older than 7 days

### 4c. Pool exhaustion monitoring — `main.py`
- Log a warning when pool acquire takes >5s
- Add pool stats to `/health` endpoint: `{"pool": {"size": 40, "free": 12, "used": 28}}`
