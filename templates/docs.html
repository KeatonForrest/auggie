API Documentation

Programmatic access to Auggie's AI-powered account research.

Quick Start

from auggie import AuggieClient
client = AuggieClient("aug_your_key")
result = client.research_and_poll("https://example.com")

Install: pip install auggie

Python SDK

The official Python SDK wraps the REST API with convenient helpers for polling and error handling.

Installation

pip install auggie

Basic Usage

Submit a research job and poll until completion:

from auggie import AuggieClient

client = AuggieClient("aug_your_key")

# Research a company (blocks until complete)
result = client.research_and_poll("https://example.com")

print(result["scores"]["composite"])      # Overall score
print(result["scores"]["pain"])           # Pain score
print(result["sections"]["talking_points"])  # Ready-to-use talking points

Bulk Research

urls = ["https://example.com", "https://acme.com", "https://widgets.io"]
bulk = client.bulk_research(urls, name="Q1 prospects")

# Poll until all complete
result = client.poll_bulk(bulk["bulk_job_id"])
for item in result["items"]:
    print(f"{item['company_url']}: {item['status']}")

Error Handling

from auggie import AuggieClient, AuggieError

client = AuggieClient("aug_your_key")

try:
    result = client.research_and_poll("https://example.com")
except AuggieError as e:
    print(f"Error {e.status_code}: {e.message}")
    # e.status_code — HTTP status (401, 402, 422, 429, etc.)
    # e.message — Human-readable error description

Getting Started

Base URL for all API requests:

https://auggie.app/v1

How it works

  1. Create an API key at /api-keys.
  2. Submit a company URL via POST /v1/research. This returns a job_id immediately.
  3. Poll for results via GET /v1/research/{job_id}, or register a webhook to be notified when the job completes.
  4. Generate outreach via POST /v1/research/{doc_id}/sequence using the completed document.

Authentication

All API requests require a Bearer token. Create API keys at /api-keys.

Include the key in the Authorization header:

Authorization: Bearer aug_your_api_key_here

Keys are shown once on creation. Store them securely — they cannot be retrieved later.

Research

POST /v1/research

Start an async research job. Returns immediately with a job ID. Costs 1 credit.

Request body

{
  "company_url": "https://example.com"
}

Response 202

{
  "job_id": 42,
  "status": "processing"
}

curl example

curl -X POST https://auggie.app/v1/research \
  -H "Authorization: Bearer aug_your_key" \
  -H "Content-Type: application/json" \
  -d '{"company_url": "https://example.com"}'

{
  "list_id": 5,
  "name": "Q1 Targets",
  "status": "analyzing",
  "total_accounts": 2

Webhooks

Register a webhook URL to receive notifications when research jobs complete, instead of polling.

POST /v1/webhooks/register

Register or update your webhook URL. Returns a secret for HMAC signature verification.

Request body

{
  "url": "https://yourserver.com/webhook"
}

Response

{
  "url": "https://yourserver.com/webhook",
  "secret": "a1b2c3...hex...",
  "active": true
}

curl example

curl -X POST https://auggie.app/v1/webhooks/register \
  -H "Authorization: Bearer aug_your_key" \
  -H "Content-Type: application/json" \
  -d '{"url": "https://yourserver.com/webhook"}'
GET /v1/webhooks

Get your current webhook configuration.

Response

{
  "url": "https://yourserver.com/webhook",
  "active": true
}

curl example

curl https://auggie.app/v1/webhooks \
  -H "Authorization: Bearer aug_your_key"
DELETE /v1/webhooks

Remove your webhook. Returns 204 on success.

curl example

curl -X DELETE https://auggie.app/v1/webhooks \
  -H "Authorization: Bearer aug_your_key"

Verifying webhook signatures

Each webhook delivery includes an X-Auggie-Signature header containing an HMAC-SHA256 hex digest. Verify it using the secret returned at registration:

import hashlib, hmac, json

def verify_webhook(payload: bytes, signature: str, secret: str) -> bool:
    """Verify an Auggie webhook signature."""
    body = json.dumps(
        json.loads(payload),
        separators=(",", ":"),
        sort_keys=True
    ).encode()
    expected = hmac.new(
        secret.encode(), body, hashlib.sha256
    ).hexdigest()
    return hmac.compare_digest(expected, signature)

Clay Integration

Use Auggie as an HTTP enrichment column in Clay to automatically research companies in your table. The dedicated /v1/clay/enrich endpoint runs synchronously and returns a flat response optimized for Clay column mapping.

Important: Set your Clay HTTP column timeout to 120 seconds. Research typically completes in 30-60 seconds, but complex companies may take longer.

POST /v1/clay/enrich

Synchronous enrichment endpoint. Runs the full research pipeline and returns a flat JSON response. Includes 24-hour caching — re-enriching the same company within 24h returns the cached result at no credit cost. Rate limited to 5 requests per 60 seconds.

Request body

{% raw %}{
  "company_url": "{{/Company Website}}"
}{% endraw %}

Response

{
  "success": true,
  "company_name": "Acme Corp",
  "company_url": "https://acme.com",
  "pain_score": 87,
  "fit_score": 75,
  "timing_score": 82,
  "composite_score": 82,
  "score_summary": "Strong pain signals...",
  "pain_reasons": "PostgreSQL scaling + 4mo backend role...",
  "business_problems": "...",
  "product_fit": "...",
  "talking_points": "...",
  "existential_data_points": "...",
  "document_id": 1523,
  "cached": false,
  "research_duration_seconds": 47.32,
  "error": null
}

curl example

curl -X POST https://auggie.app/v1/clay/enrich \
  -H "Authorization: Bearer aug_your_key" \
  -H "Content-Type: application/json" \
  -d '{"company_url": "https://example.com"}'

Field mapping

All response fields are flat — no nested paths needed. Map these fields in Clay:

Field Description
pain_score Pain score (0-100)
composite_score Overall opportunity score (0-100)
fit_score ICP fit score (0-100)
timing_score Buying timing score (0-100)
score_summary One-line score explanation
pain_reasons Key pain signals identified
business_problems Identified business problems
product_fit Product fit analysis
talking_points Ready-to-use talking points
document_id Document ID (use with sequence endpoint)

You can also use the async POST /v1/research endpoint with polling if you prefer — see Research above.

Automation Platforms

Use Auggie's REST API in any automation tool that supports HTTP requests. The pattern is the same for all platforms:

General Setup

  1. Create an API key at /api-keys
  2. Add an HTTP request step in your workflow
  3. Configure a POST to https://auggie.app/v1/research with header Authorization: Bearer aug_your_key
  4. Send the body {"company_url": "https://example.com"}
  5. Poll GET /v1/research/{job_id} until status is completed, or use a webhook to get notified
  6. Use the returned scores and sections.talking_points to route leads or draft messaging
curl -X POST https://auggie.app/v1/research \
  -H "Authorization: Bearer aug_your_key" \
  -H "Content-Type: application/json" \
  -d '{"company_url": "https://example.com"}'

n8n

Option A — Polling workflow

Best when you want a self-contained workflow with no external webhook URL.

  1. Add an HTTP Request node. Set Method to POST, URL to https://auggie.app/v1/research.
  2. Under Authentication, choose Generic Credential Type → Header Auth. Set Name to Authorization, Value to Bearer aug_your_key.
  3. Set Body Content Type to JSON and add: {"company_url": "https://example.com"}
  4. Add a Wait node → set to 5 seconds.
  5. Add a second HTTP Request node. Method: GET, URL: https://auggie.app/v1/research/{% raw %}{{ $('HTTP Request').item.json.job_id }}{% endraw %}. Same auth header.
  6. Add an IF node. Condition: {% raw %}{{ $json.status }}{% endraw %} is not equal to completed.
  7. Connect the IF true output back to the Wait node (creates a loop). Connect false (completed) to your next action.

Flow: HTTP Request → Wait → HTTP Request (poll) → IF → loops back to Wait or continues.

Option B — Webhook workflow (recommended)

Eliminates polling. Auggie calls your n8n webhook when research finishes.

  1. Create a new workflow starting with a Webhook trigger node. Copy its Production URL (e.g. https://your-n8n.com/webhook/abc123).
  2. Register that URL with Auggie — see the Webhooks section above.
  3. In a separate workflow (or triggered by a Schedule/form), add an HTTP Request node that POSTs to /v1/research to kick off jobs.
  4. When research completes, Auggie POSTs the results to your Webhook trigger. The payload includes scores, sections, and company_url.
  5. Add downstream nodes to route leads, update a Google Sheet, send a Slack message, etc.
Bulk research from a spreadsheet

Process an entire list of companies from Google Sheets or Airtable.

  1. Add a Google Sheets (or Airtable) node to read rows with a company_url column.
  2. Add an HTTP Request node. POST to https://auggie.app/v1/research/bulk with body:
{
  "urls": {% raw %}{{ $json.rows.map(r => r.company_url) }}{% endraw %},
  "list_name": "n8n bulk import"
}
  1. Poll GET /v1/research/bulk/{id} for progress, or use a webhook to get notified when the batch completes.

Make (Integromat)

Option A — Polling scenario
  1. Add an HTTP > Make a request module. Set Method to POST, URL to https://auggie.app/v1/research.
  2. Under Headers, add Authorization: Bearer aug_your_key and Content-Type: application/json.
  3. Set Request content to {"company_url": "https://example.com"}. Check Parse response.
  4. Add a Sleep module (Tools > Sleep) set to 5 seconds.
  5. Add a second HTTP > Make a request module. Method: GET, URL: https://auggie.app/v1/research/{% raw %}{{1.body.job_id}}{% endraw %}. Same auth header.
  6. Add a Router module. Route 1 filter: status not equal to completed — loop back to the Sleep module. Route 2 (fallback): continues to your next action.

Flow: HTTP (POST) → Sleep → HTTP (GET poll) → Router → loops or continues.

Option B — Webhook scenario (recommended)
  1. Create a new scenario starting with a Webhooks > Custom webhook trigger. Copy its URL.
  2. Register that URL with Auggie — see the Webhooks section above.
  3. In a separate scenario, add an HTTP module that POSTs to /v1/research to start jobs.
  4. When research completes, Auggie sends the full result to your webhook trigger. Add downstream modules (Google Sheets, Slack, email, etc.) to handle the data.
Bulk research from a spreadsheet
  1. Add a Google Sheets > Search Rows module to fetch rows with company URLs.
  2. Add an HTTP > Make a request module. POST to https://auggie.app/v1/research/bulk with body:
{
  "urls": {% raw %}{{map(2.bundles; "company_url")}}{% endraw %},
  "list_name": "Make bulk import"
}
  1. Poll GET /v1/research/bulk/{id} for progress, or use a webhook for completion notification.

Zapier

Option A — Polling Zap
  1. Add a trigger (Schedule, new row in Google Sheets, etc.).
  2. Add a Webhooks by Zapier > Custom Request action. Method: POST, URL: https://auggie.app/v1/research.
  3. Add headers: Authorization | Bearer aug_your_key and Content-Type | application/json.
  4. Set Data to {"company_url": "https://example.com"}.
  5. Add a Delay by Zapier step set to 30 seconds (Zapier's minimum).
  6. Add another Webhooks by Zapier > Custom Request. Method: GET, URL: https://auggie.app/v1/research/{% raw %}{{steps.2.job_id}}{% endraw %}. Same headers.
  7. Add a Filter by Zapier step: only continue when status equals completed. (Zapier doesn't natively loop — see the webhook option below for a cleaner approach.)
Option B — Webhook Zap (recommended)

Avoids polling entirely. The cleanest Zapier integration.

  1. Create a new Zap with a Webhooks by Zapier > Catch Hook trigger. Copy the webhook URL Zapier gives you.
  2. Register that URL with Auggie — see the Webhooks section above.
  3. In a separate Zap (triggered by a schedule, form, or spreadsheet row), use Custom Request to POST to /v1/research.
  4. When research completes, Auggie sends the full result to your Catch Hook. Add downstream actions (Google Sheets row, Slack message, email draft, CRM update, etc.).
Bulk research

Zapier processes items one at a time, so use the bulk endpoint to batch them.

  1. Use a Code by Zapier (JavaScript) step to collect URLs from previous steps into an array.
  2. POST to https://auggie.app/v1/research/bulk:
{
  "urls": ["https://acme.com", "https://globex.com"],
  "list_name": "Zapier bulk import"
}
  1. Use a Catch Hook Zap to receive the completed results via webhook.

Error Codes

Status Meaning
401 Missing or invalid API key.
402 No credits remaining. Purchase more at /billing/buy-credits.
404 Resource not found (job, document, or webhook).
422 Invalid request body or company URL (e.g., private IP, malformed URL).
429 Rate limit exceeded. Check the Retry-After header.

Rate Limits

Limits are per API key, using a sliding window. Exceeding a limit returns 429 with a Retry-After header.

Endpoint Group Limit
POST /v1/clay/enrich 5 requests / 60 seconds
POST /v1/research, POST /v1/enrich 10 requests / 60 seconds
POST /v1/research/bulk, POST /v1/lists, POST /v1/lists/{id}/analyze 2 requests / 60 seconds
POST /v1/research/{id}/sequence 20 requests / 60 seconds
All other endpoints (GET /v1/research, GET /v1/ping, webhooks) 60 requests / 60 seconds
